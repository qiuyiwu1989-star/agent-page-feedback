# 在飞书里拍板（飞书桥，可选）

默认的飞书通知用群机器人的 webhook：只能「收」，卡片上的按钮只能跳到网页。
飞书桥（`tools/feishu_bridge.py`）用飞书**自建应用的长连接**（WebSocket），让负责人在飞书卡片上直接点「选 A」「先不做」「通过」，
点击经长连接回到服务器，记成任务中心里的正式决定。不需要公网回调地址，任务中心本身不用改。

## 飞书开放平台里要做的（负责人做，一次）
1. 自建应用 → 「添加应用能力」→ 机器人。
2. 「权限管理」开：发消息（`im:message:send_as_bot`）、读私聊消息（`im:message.p2p_msg:readonly`）、读群里 @机器人 的消息（`im:message.group_at_msg:readonly`）。
3. 「事件与回调」：
   - 事件配置 → 订阅方式选「使用长连接接收事件」→ 添加事件「接收消息 v2.0」（`im.message.receive_v1`）。
   - 回调配置 → 订阅方式选「使用长连接接收回调」→ 添加回调「卡片回传交互」（`card.action.trigger`）。
   - 保存订阅方式时，飞书会检查长连接是否在线，所以先把飞书桥跑起来。
4. 「版本管理与发布」→ 创建版本并发布（权限改动要发布才生效）。
5. 把机器人拉进要收卡片的群。

## 服务器上
```bash
python3 -m venv /opt/feishu-bridge/venv && /opt/feishu-bridge/venv/bin/pip install websocket-client   # 长连接协议在 feishu_bridge.py 里实现，常驻内存约 16MB
# 配置写在只有服务账号能读的文件里（chmod 600），不要进仓库：
#   FEISHU_APP_ID、FEISHU_APP_SECRET、FB_API（任务中心，本机地址）、FB_ADMIN_CODE、FB_OWNER_NAME、FB_SITE_URL
# 用 systemd 常驻（EnvironmentFile 指向上面的文件，Restart=always）
```

## 管几个项目
一个机器人可以管几个任务中心：`FEISHU_PROJECTS` 指向一个 JSON 文件（只有服务账号能读），每项
`{"key": "hs", "name": "好设计", "alias": ["好设计"], "api": "http://127.0.0.1:端口/api/fb/", "admin_code": "负责人口令", "site_url": "https://网站/api/fb/"}`，第一项是默认项目。卡片标题前会标【项目名】。

## 在飞书里提需求
给机器人发一句话（不是命令），就在任务中心开一张需求（不依附页面），署名「负责人（飞书）」：
- 「好设计：首页卡片太大了」→ 开在好设计；没写项目就开在默认项目。
- 「让 Codex 把……」「交给 Codex：……」→ 负责方 Codex；没写就交给 Claude。
- 负责人本人提的、意思明确的需求，定时处理的 agent 下一轮直接做，做完交付报告，卡片会发回飞书等验收。
- 「进度」：各项目等你定 / 等你验收 / 在做 / 新提的数量。

## 用法
- 第一次：日志里会打印一个六位绑定码。负责人私聊机器人发「绑定 六位码」，就登记为负责人（只有登记过的人点按钮才算数）。
- 在群里 @机器人「在这里提醒」：以后「待你决定」「待你验收」的卡片发到这个群。
- @机器人「决策台」：把还没定的事发一遍。
- 卡片：待决定 → 每个选项一个按钮 +「先不做」+「写意见 / 看全部」（打开网页）；待验收 →「通过」+「要再改」（打开网页写意见）。
- 点过的卡片会变成「已定」；在网页上已经定过的，旧卡片再点会提示过期，不会重复记。

## 安全
- 负责人口令只在服务器上，用来把负责人在飞书上的点击记成决定；不会发到飞书。
- 应用凭据泄露过就在开放平台「凭证与基础信息」里重置 App Secret，再改服务器上的配置文件。
